# 核心设计与取舍

本文解释当前实现能从代码验证的设计理由，不把合理推导写成未记录的开发历史。区间扫描和 CIDR 分解属于已有算法；贡献在于完整的 MoonBit 值模型、双栈语义、边界处理及可验证实现。

## 1. 固定宽度的数值内核，大整数只用于需要它的接口

[`Address`](../address.mbt) 保存地址族和四个按网络顺序排列的 `UInt32`。IPv4 与 IPv6 始终分族，包括 IPv4-mapped IPv6；比较先检查族，再逐字比较，避免把两个地址空间的同一个数字混为一谈。移位、掩码、进位和前后继可直接作用在固定宽度上。

替代方案是全程使用 `BigInt`，实现部分算术更简单，但每次字节转换也经过大整数会增加中间工作。当前 `IpAddress::from_bytes/to_bytes` 直接按网络字节序拆装；历史 native 微基准显示这两条路径相对原实现有改善，范围及方法见 [TESTING](TESTING.md#字节转换基准)。这不是整个库或所有后端的性能保证。

两个 `UInt64` 也是可行设计，本项目没有提供与它的性能对比，不能宣称四个 `UInt32` 最快。当前表示的代价是跨字进位和掩码需要显式实现，因此白盒回归逐位检查全部 129 个 IPv6 前缀，并测试 32/64/96 位边界。`num_addresses`、公开整数转换和索引仍使用 `BigInt`：IPv6 `/0` 的地址数为 `2^128`，需要 129 位无符号计数。

## 2. 规范区间，适合批量集合运算

[`IpSet`](../set.mbt) 存储排序、互不重叠且不相邻的闭区间。构造时复制输入数组、排序并归并；输出区间数组也复制，调用者不能通过修改数组改变已构造集合。

设规范化后两组区间数量为 m、n：成员查询二分查找，复杂度 O(log m)；并、交、差和子集判断使用单调扫描，复杂度 O(m+n)，额外输出取决于结果大小。子集判断直接在首个缺口返回，只使用 O(1) 额外空间。复杂度针对区间数，不是输入地址数；大量离散地址仍会产生大量区间。

替代方案有哈希地址集合和前缀树。前者不适合枚举 IPv6 大网段，后者适合频繁增量更新或最长前缀匹配。本库的不可变区间设计面向批处理成员关系及集合代数，不承诺路由查找或动态更新最优。每次构造都有复制和排序成本。

## 3. 闭区间与最大地址

半开区间 `[lo, hi)` 通常更便于计数，但 IPv6 全空间的右端点是 `2^128`，无法放入现有 128 位地址类型。当前用闭区间 `[lo, hi]`，前驱与后继返回 `Option[Address]`；到达最大值返回 `None`，不能回绕至零。

差集中，一个排除区间可能横跨多个来源区间；覆盖当前来源末尾后保留该排除项，下一来源继续使用。归并时也先判断地址族，再判断重叠或相邻。对应测试包括 `one exclusion spanning several source intervals is retained`、`endpoint exclusions never wrap and full spaces stay compact`，位于 [set_test.mbt](https://github.com/tc-adventureking/moon-ipset/blob/main/set_test.mbt)。

CIDR 分解每次选择当前起点对齐、且不超出区间末尾的最大块。完整地址族直接输出 `/0`；按输出块推进，不枚举主机。其正确性检查包括有限集合的独立位掩码 oracle、最大地址及跨字边界案例，不主张已完成形式证明。

## 4. 对象身份与数值覆盖分别定义

[`IpAddress`](../address_api.mbt) 增加 IPv6 scope，`IpNetwork` 和 `IpInterface` 保留各自语义。`fe80::1%a` 与 `fe80::1%b` 是不同对象，所以 `Eq`、`Hash` 和总序都考虑 scope，确保比较为零与相等一致。

但集合运算计算数值覆盖，不能借 scope 推断实际接口可达性。`compare_networks` 按族内数值地址与前缀比较，`subnet_of`、范围汇总和排除按数值处理；转换到旧 `Address/Cidr/IpSet` 时 scope 不保留。两种比较不是别名，调用者必须选择需要的语义。

直接复制 Python 的所有细节会保留部分不一致行为；完全忽略 scope 又会破坏对象身份。当前采用显式区分，并在 [COMPATIBILITY](COMPATIBILITY.md) 列出 11 类有意差异和不复刻的动态协议。参考版本固定，不能把后续 Python 或 IANA 变化静默算作一致。

## 5. 惰性迭代与受检失败

[`IpNetwork::iter/hosts/subnets`](../network_api.mbt) 返回 `Iter`，调用方可 `take(n)`，而不用先分配 `/64` 的全部主机。惰性并不消除遍历成本：对巨大网络完整消费仍然不可行。`/31`、`/32`、`/127`、`/128` 主机端点有独立约定和回归。

构造及算术使用 `IpError` 表达非法地址、前缀、范围和非零主机位，拒绝溢出。新 `IpNetwork` 默认严格，旧 `Cidr` 的宽松默认保持兼容。显式构造方法取代 Python 的动态参数组合，避免把歧义留给运行时；代价是 API 方法较多，调用方式并非逐字兼容。

## 6. 分层验证避免相同实现互相证明

- 固定 CPython 源码提供地址、网络和接口的独立语义参考；严格一致与有意适配分开统计。
- 有限地址集合使用独立 bitmask oracle，检查集合代数及 CIDR 规范覆盖。
- 字节转换除往返外，使用独立 BigInt 路径核对数值，防止编码和解码的同向错误互相抵消。
- 四后端实际执行；官方 ZIP 解包后由独立消费模块验证，避免只测试工作树。
- 公开分层向量及故障注入入口见 [conformance](https://github.com/tc-adventureking/moon-ipset/tree/main/conformance)。历史修复与审查意见的证据区别见 [REVIEW_CASES](REVIEW_CASES.md)。

上述机制能提高发现和防止回归的能力，不代表所有输入、长期负载或真实防火墙部署均已验证。
